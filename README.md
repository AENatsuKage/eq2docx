# eq2docx

English | [中文](README.zh-CN.md)

**Turn a display LaTeX equation on the clipboard into a one-equation `.docx` with pandoc — paste it into Word as a native, editable OMML equation.**

Writing a paper in Word while doing the math in AXMath? The usual loop is painful: export LaTeX, create a markdown file by hand, run pandoc, open the docx, select the equation, copy, switch back to Word, paste. `eq2docx` collapses that into one command.

```
AXMath  Ctrl+T  →  eq2docx -o EQ01  →  open EQ01.docx  →  copy the equation  →  paste into Word
```

The LaTeX is handed to pandoc **verbatim** — the script does not rewrite, normalize or "fix" your math. If it renders in a markdown preview, it renders in the docx.

## Requirements

- Windows with PowerShell. `pwsh` 7 is recommended; Windows PowerShell 5.1 works too (the script carries a UTF-8 BOM).
- [pandoc](https://pandoc.org/installing.html), any reasonably recent version. Tested with 3.13 and 3.8 — equation output is identical.

## Quick start

First get the files onto your machine: clone the repo (or download the ZIP and extract it) into a folder of your choice — `D:\tools\eq2docx` is used as the example path below.

```cmd
:: clone once (or extract the ZIP to the same place)
git clone https://github.com/AENatsuKage/eq2docx.git D:\tools\eq2docx

:: then, from that folder
cd /d D:\tools\eq2docx
pwsh -File eq2docx.ps1 -Init -PandocPath "D:\tools\pandoc\pandoc.exe"
```

`-PandocPath` is optional: without it, `-Init` auto-detects pandoc from the environment, `PATH`, or common install locations (see [How pandoc is located](#how-pandoc-is-located)).

`-Init` does three things:

1. saves the pandoc path to `eq2docx.config.json`, so you never type it again;
2. generates `eq2docx.cmd`, a small shim so that **`eq2docx` works in a plain `cmd` window** (`cmd` cannot run a `.ps1` by name);
3. appends this folder to your user `PATH` and broadcasts `WM_SETTINGCHANGE`.

Open a **new** terminal afterwards — environment changes only reach new processes. Verify:

```cmd
eq2docx -Check
```

It prints the pandoc path it resolved, its version, and where the config file lives.

## Usage

```cmd
:: 1. copy the formula to the clipboard (AXMath: Ctrl+T, or select the whole $$...$$ block and Ctrl+C)
:: 2.
eq2docx -o EQ01
```

Output: `EQ01.md` (the clipboard text, unchanged — written as UTF-8 without BOM) and `EQ01.docx` (that single display equation). Both land in the script folder unless `-OutDir` says otherwise.

Open the docx, click the equation, copy it, paste into your target document — Word turns it into an editable math object.

## Parameters

| Parameter | Purpose |
|---|---|
| `-o <name>` | Output basename; `EQ01` → `EQ01.md` + `EQ01.docx`. Omit it and you get `EQ_yyyyMMdd_HHmmss` |
| `-OutDir <dir>` | Output folder; defaults to the script folder, created if missing |
| `-InputFile <file>` | Read from a file instead of the clipboard — handy for re-runs and testing |
| `-PandocPath <exe>` | pandoc for this run only. An invalid path is a hard error, not a silent fallback |
| `-Init` | Write config + generate `eq2docx.cmd` + add this folder to `PATH` |
| `-Check` | Print the resolved pandoc path, version and config location, then exit |

## How pandoc is located

First match wins:

1. `-PandocPath` (this run)
2. environment variable `EQ2DOCX_PANDOC` (runtime override, beats the config file)
3. `eq2docx.config.json`
4. environment variable `PANDOC`
5. `pandoc` on `PATH`
6. common install locations: `%LOCALAPPDATA%\Pandoc\pandoc.exe`, `C:\Program Files\Pandoc\pandoc.exe`, `D:\anaconda3\Library\bin\pandoc.exe`

All three styles therefore work: rely on the saved config, override per shell with `set EQ2DOCX_PANDOC=...`, or override per call with `-PandocPath`.

## Exit codes

| Code | Meaning |
|---|---|
| 0 | success |
| 1 | `-Init` could not find pandoc |
| 2 | pandoc not found, or `-PandocPath` is invalid |
| 3 | empty input, illegal output name, or input file missing |
| 4 | pandoc conversion failed |

## Built-in check

After converting, the script unzips the docx and looks for `<m:oMath` in `word/document.xml`:

- `√ Office equation (OMML) generated` — the equation is a real math object.
- `! no OMML equation found` — the input was not wrapped in `$...$`, so pandoc treated it as plain text. The docx is still produced; it just contains a paragraph of LaTeX source.

## Troubleshooting

**`eq2docx` is not recognized in cmd.**
You skipped `-Init`, or you did not open a new window (the `PATH` broadcast only affects new processes).

**Garbled console output.**
The console code page and PowerShell disagree about encoding. `.md` files are written as UTF-8 and are unaffected; run `chcp 936` (or `chcp 65001`) so the console matches.

**The docx contains only the formula, no body text.**
By design: the input is one display equation, the output is one display equation. For a full document, call pandoc directly — `pandoc your.md -o your.docx`.

**The formula shows up as grey LaTeX text in Word.**
The text handed to pandoc was not wrapped in `$$...$$`, or the delimiters got split across lines. The script warns about this but will not guess for you.

**Moving to another machine.**
Copy `eq2docx.ps1` (plus the demo files if you want them), then run `-Init -PandocPath "<local pandoc.exe>"` once — the `.cmd` shim and the config are regenerated. Files that arrived from a network share or a USB stick need `Unblock-File` before RemoteSigned will run them.
